# Source reconstruction status

This directory is a **best-effort source reconstruction** of the binary identified in `BINARY-MANIFEST.txt`. It was generated by decompiling the user-provided JAR with Vineflower 1.12.0 and normalizing its resources into a conventional `src/main/java` and `src/main/resources` layout.

## Inventory

- 227 Java source files reconstructed (one for each top-level class in the JAR; nested/inner classes are represented in their containing source files).
- 47 non-Java resources and metadata files copied from the JAR.
- 357 compiled `.class` entries were present in the JAR.
- No Sodium implementation classes were found bundled in the JAR; Sodium is declared as a required dependency (`0.9.2`).

## Known gap

Vineflower reported that it could not decompile `TerrainResidency.drainPendingUploadsLocked(TerrainGpuHost)`. That method has been **manually reconstructed from the bytecode embedded in the decompiler output comments**. The method is explicitly marked in the Java source as reconstructed, not recovered from original author source. It has not been independently verified by rebuilding the project or comparing runtime behavior.

## Build/reproducibility status

The JAR does not contain the original Gradle build scripts, Gradle wrapper, mappings configuration, or dependency lock files. Those were not present in the uploaded artifact and are not recreated here. Consequently, this directory is not currently a verified, reproducible Gradle project and should not be described as the original source checkout.

For a fully corresponding source release, recover the original project build files and perform a clean build against the exact published JAR/version. If the original files cannot be recovered, keep this reconstruction clearly labeled as decompiled/reconstructed and do not claim that it is a verified reproducible source build.
